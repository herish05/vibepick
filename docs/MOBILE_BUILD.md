# Mobile build

The app is Expo (React Native, expo-router). Because VibePick registers as a **share target** (`expo-share-intent`), it needs a **development build**; Expo Go cannot receive shares.

## Setup
```bash
cd mobile
npm install --legacy-peer-deps
export EXPO_PUBLIC_API_URL=http://10.0.2.2:3000   # Android emulator → host. Real device: your LAN IP
```
Default (`app.json` → `extra.apiUrl`) is `http://10.0.2.2:3000`. Start the backend first (`docker compose up`).

## Android
Requires JDK 17 and the Android SDK.
```bash
npx expo prebuild --platform android
npx expo run:android          # emulator or USB device
```
Intent filters (`ACTION_SEND`/`ACTION_SEND_MULTIPLE`, `image/*`, `video/*`) are generated by the `expo-share-intent` plugin. Test by sharing a photo from Gallery or Instagram's share sheet and picking VibePick. Cleartext HTTP to a LAN backend needs a debug build; production must use HTTPS.

## iOS
Requires macOS + Xcode (or EAS Build). The Share Extension target is generated by the plugin at prebuild:
```bash
npx expo prebuild --platform ios && npx expo run:ios
# or: eas build --profile development --platform ios
```
Configure your Apple team and an App Group for the extension. This cannot be built on Linux.

## Release
Use EAS Build (`eas build --platform all --profile production`), set `EXPO_PUBLIC_API_URL` to your HTTPS API, and replace the `app.vibepick.mobile` identifiers if needed.

## Checks
`npm run lint && npm run typecheck && npm test` (13 unit tests). CI also runs `expo prebuild --platform android --no-install`.

## Status
Typecheck, lint, unit tests and Android prebuild pass. **The share flow has not been run on a device or emulator**, so do that before relying on it. Deep link `vibepick://` and Instagram hand-off (`instagram://story-camera`) behave differently across Instagram versions and may fall back to opening the app/store.
